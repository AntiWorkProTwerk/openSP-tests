# Sample-write and firmware-restoration audit

This read-only audit covers sealed kit13 and installed final07, candidate SHA256 `7881b5c18e4cdd83a405349109c05822b23bd6e38f1df37b264eafe558756f48`. The [incident record](../../../../sp404mk2/analysis/hardware/opensynth_n1_missing_pads_20261006/README.md) reports missing pads after physical destination selection fails. No START, captured phrase, SAVE or saved-pad playback was reported. File deletion, affected project and cause remain unknown.

The host patcher authenticates official firmware and source inputs, writes private build artifacts, and inspects source, objects, recipes, APP1 bytes and P6S restoration. Its supplied restoration is another firmware image. The source-only ZIP contains no owner sample files, PADCONF backup or hardware capture. Static receipts and USB programming readback do not establish data preservation or a project backup.

In the sealed `adapter/src/sp_synth_project_save_v552.c`, `path()` constructs the selected project's `B:/ROLAND/SP-404MKII/PROJECT_.../PADCONF.BIN` path. The adapter selects an active transaction on its SMPL worker, checks current project and setting, descriptor ownership, 64 writes totaling 52,000 bytes, stat, sync and close. `run()` sets the PARAM+28 dirty byte and calls native saver `800CF218`. It also leaves that dirty byte set after a qualified fault. There is no pre-existing metadata snapshot, backup copy or content rollback in this adapter. Checks after partial writes cannot undo an already changed file.

Unselected adapter calls delegate to native file operations. In `joined/generated/capture.c`, `sp_synth_capture_timed_v552_project_save()` delegates to native `800CF218` when no capture owner exists or its phase is FREE. The selected path requires matching token, worker and SAVING phase. These narrow selected-SAVE checks do not exclude native loading, idle dirty saves or fallback metadata persistence. They do not show that any such path ran on the owner's SP.

The same capture source contains native temporary-file cleanup and unlink calls. Their existence does not establish deletion of occupied pad samples. The project writer is a metadata serialization path; sampler startup, native FILEIF admission and project-loader failure paths require their own investigation. Addresses and owner extents here refer only to Roland v5.52/final07.

The source-owned B2 writer targets its bounded APP1 NOR region. Its restoration transaction does not export or restore an owner project. Reinstalling P6S might change firmware behavior, but missing-pad recovery through that action has not been established. The guard therefore carries explicit false sample/project backup claims and grants no restoration action.

The current patcher gap is preservation evidence for existing data. Its fixed source contract describes direct capture and source joins; the byte inspector never compares a populated owner's sample set or PADCONF before and after native boot/load/idle/save behavior. Root's next investigation compares populated P6S/N1 paths with all 160 pad rows, sample bytes, names, markers and other-project sentinels. The guard requires incident resolution and a new candidate-bound preservation authority before eligibility can change. Frozen kit13 stays historical and withdrawn.
